# 구독 갱신 의사결정 제품 계획

## 판단과 검증 가설

현재 **유료 준비 상태는 미검증**이다. 코드 구현, 로컬 테스트 성공, 실제 고객 가치 검증, 운영 배포 검증은 각각 별도의 완료 조건이다.

2026-10-05 측정 후속 작업은 [마케팅 준비 키트](./marketing/README.md)와 [선택 동의 집계 계약](./marketing-runtime.md)에서 관리한다. 기존 온디바이스 분석과 별도의 일별 마일스톤 집계이며, 사용자 수·활성화율·퍼널·리텐션을 제공하지 않는다. 실제 운영 활성화 여부는 [마케팅 릴리스 기록](./marketing-release-20261005.md)을 따른다. 아래 원래 계획의 고객 가치 검증은 이 집계만으로 완료되지 않는다.

- 우선 타깃 가설: 여러 구독과 연간 결제를 관리하며 자동 갱신으로 낭비한 경험이 있는 직장인.
- 핵심 약속: **다음 결제 전에 계속 쓸지 결정하고, 잊고 나가는 구독료를 줄인다.**
- 2026-10-06 계속 진행 요청에 따라 월 990원 / 연 9,900원을 준비 기준으로 삼는다. 과거 월 2,900원 가설을 대체한다. 최종 판매 조건·지불 의향·과금 개시는 미검증이며 [가격/결제 준비 기록](payment-readiness-20261006.md)을 따른다.
- AI 기능, 은행 연동, B2B 확장은 핵심 여정의 가치 검증 이후로 미룬다.

## 우선순위와 수락 조건

| 단계 | 작업 | 수락 조건 |
|---|---|---|
| P0 | 실제 고객 여정 | 샘플 체험 → 내 데이터 시작 → 구독 등록 → 기준일 설정 → 예정액 확인 → 갱신 결정 → 재방문을 관찰. 로컬 E2E는 기술 검증이며 고객 관찰을 대신하지 않는다. |
| P0 | 비월간 결제 정확성 | 월·분기·연간 주기는 기준일에 고정. 말일·윤년·과거 및 미래 기준일 검증. 기준일 없는 기존 데이터는 일정 미확인으로 표시하고 잘못된 알림을 보내지 않는다. 월환산 비용과 실제 결제액을 구분한다. |
| P0 | 데이터 안전 | 로컬 프로필 전환으로 다른 사용자의 저장 내용을 덮어쓰지 않는다. 서버 동시 수정은 버전 충돌로 중단하며 최신 버전을 재조회했다는 이유만으로 덮어쓰기를 허용하지 않는다. 다운로드 전 복구본을 보존하고 늦은 응답을 다른 계정에 적용하지 않는다. |
| P1 | 안전한 온보딩·등록 | 처음에는 내 빈 공간. 샘플은 별도 프로필. 내 데이터 복귀 시 기존 항목 보존. 빠른 등록 후 사용자가 기준일을 직접 설정할 수 있다. |
| P1 | 의사결정 요약 | 월환산 금액, 다음 30일 실제 예정액, 날짜 미확인 항목을 구분. 기간 경계와 동일 기간의 복수 결제를 빠뜨리지 않는다. |
| P1 | 갱신 검토 | 유지 / 해지 예정 / 변경 검토 / 완료 상태를 저장·복원. 계획만으로 실제 절감을 주장하지 않는다. 사용자 확인 절감은 별도로 표시한다. |
| P1 | 자동 동기화 | 초기 기준본 합의와 사용자 선택 이후에만 실행. 충돌·계정 전환·로컬 저장 실패 시 중단. 손실 방지 테스트가 전제다. |
| P2 | 최소 운영 측정 | 금액·항목명·이메일·계정/워크스페이스 식별자를 전송하지 않는 최소 이벤트 설계. 수집 목적·보존기간·동의·삭제 절차 확정 후 운영 수집 도입. |
| P2 | 유료 베타 | 10~20명 모집, 핵심 여정과 반복 사용 확인, 가격 수용성 인터뷰 후 별도 과금 승인. |

## 구현 단계

1. 기존 미커밋 계정 삭제·훅 리팩토링·온디바이스 분석을 보존하고 독립 검토한다.
2. 결제 기준일과 검토 필드를 shared → API/Prisma → 로컬 저장 → 백업/CSV → 입력 UI → 예측/알림 전체 경로에 반영한다. 스키마 마이그레이션은 파일만 작성한다.
3. 샘플/내 데이터 공간 분리와 안전한 서버 동기화를 구현한다.
4. 순수 계산·직렬화·데이터 손실 방지 테스트, 격리 DB API 테스트, 로컬 브라우저 여정을 실행한다.
5. 독립 리뷰의 발견 문제를 수정하고 검증 결과를 별도 실행 기록에 남긴다.

## 베타 검증 설계

- 모집: 타깃 조건에 맞는 10~20명. 구독 관리 방식과 최근 자동 갱신 경험을 먼저 인터뷰한다.
- 관찰: 도움 없이 첫 구독과 기준일 등록 가능 여부, 예정액 이해, 갱신 전 결정 완료 여부, 다음 주 재방문 이유.
- 성공 판단 자료: 등록 완료 비율, 날짜 설정 비율, 갱신 결정 완료 비율, 7일/30일 재방문, 확인 절감 사례, 월 990원 / 연 9,900원 지불 의향 및 실제 결제 전환. 수치 목표는 모집 전 정하고 결과를 본 뒤 소급 변경하지 않는다.
- 잠재 절감: 해지/변경 검토 중인 금액의 추정치. 실제 절감: 사용자가 실행 결과를 확인한 금액. 두 값을 합산해 성과처럼 표시하지 않는다.
- 현재 온디바이스 analytics는 각 브라우저의 사용 기록일 뿐이다. **이를 통해 운영자가 가입→활성화→재방문→유료 전환율을 측정할 수 없다.** 네트워크 수집이 없다는 사실을 전환 측정 완료로 보고하지 않는다.
- P2 수집 후보: 체험 시작, 첫 등록 완료, 날짜 설정 완료, 갱신 결정 완료, 재방문, 베타 신청. 이벤트 이름과 집계에 필요한 최소 정보만 허용하고 개인정보·자유 텍스트·금액을 제외한다. 집계 분모/중복 제거와 익명성 사이의 설계를 먼저 검토한다.

## 운영 경계

FE는 Cloudflare, BE와 프로덕션 DB는 OCI다. Mac CI와 on-demand staging은 기본 꺼짐을 유지한다. 오래된 README, 추정 생성한 `.ai/infra.yaml` 및 과거 배포 문서는 운영 근거가 아니다.

운영 변경은 최신 gamja-ops 저장소 위치와 현재 설정을 직접 확인한 뒤에만 가능하다. 이번 로컬 구현에는 배포나 프로덕션 마이그레이션을 포함하지 않는다. 비용 발생 및 프로덕션 DB 변경은 Owner 승인이 필요하다. 실제 고객 관찰, 유료 베타 모집, 운영 알림 전달, 프로덕션 마이그레이션/배포는 외부 후속 검증 항목이다.
